A folder of plates goes in. A published book comes out.

Checked, sealed, timestamped and minted with a DOI — by one file, on your own machine, with your own tokens. Nothing is uploaded until you type the word.

$ curl -O https://raw.githubusercontent.com/zistgah/matba/main/matba.py
$ python3 matba.py serve      # http://127.0.0.1:8710

Or set a book here, now, with nothing installed: open the composing room — it runs in this tab, hashes your plates in the browser, and exports a payload the press can set.

The chase

It will not print on a broken forme.

On a press, plates are locked into a chase before anything is printed; if the lockup is wrong, you do not take the impression. These eight checks are matba's lockup. Every one of them is here because that exact defect once reached a permanent record. Open a plate to read which.

QuoinForme
locked

doctor exits 1 on any failure, and build refuses to run. You cannot reach the forge, and you certainly cannot reach a DOI, on input that fails here.

The impression

Three stages, and what each one will not do.

Every button in the local interface is one of these commands, so anything you can click you can script. Push and mint each ask for a word typed exactly; a mismatch exits 3 and records nothing.

  1. Stage

    matba run SLUG stage

    Clones the template, lays the plates in, runs every check.

    Writes nothing to the forge. Nothing to Zenodo. Nothing above your working directory.

  2. Push

    matba run SLUG push

    Creates the repository if it is absent, seals a manifest, pushes, verifies, turns on Pages.

    Will not report success on a push that did not land: it reads the remote back and dies unless it matches.

  3. Mint

    matba run SLUG mint

    Timestamps the artefact, mints through Zenodo, records the DOI back, re-seals, pushes again.

    Will not invent a DOI. If the publisher returns none, it stops rather than write a plausible one.

Setting the book

Six commands, start to finish.

$ matba new geometry --title "The Geometry of X" --repo you/geometry
$ matba intake geometry ~/plates          # hashes once, refuses duplicate bytes
$ matba bulk   geometry rows.tsv          # file ⇥ title ⇥ subtitle ⇥ part ⇥ topics ⇥ lead
$ matba set    geometry cover.png --cover
$ matba doctor geometry                   # exits 1 on any failure
$ matba build  geometry                   # payload, seeder, tarball
Where things live
MATBA_HOME holds one directory per book. Nothing is written outside your working directory.
Tokens
Read from a file by path, never inlined, never in a flag, never in a commit. Set ZENODO_TOKEN_PATH.
In Colab
The notebook runs the same engine with no local server. Mount Drive, point at a folder, fill the plate table, type the gate words.
What it drives
git, the forge client, the DOI client, and a book template. It reimplements none of them, and it reads a tool's interface at run time rather than assuming a remembered one.
One engine
matba emits a single generic seeder, parameterised per book. It exists because three books were once published by three copies of one script, each inheriting the last one's defects.
The composing room
A static page: drop plates, sort them, let the cycler write descriptions with whichever AI you use, split one plate into several chapters, attach exercises, export. Open it — no install, no account, no key.
Reuse
Start a book from one you already made: parts, keywords, related identifiers and the author block come across. Then retrieve the live state of any book, whenever you want it.
